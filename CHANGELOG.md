# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [0.8.0] - 2026-10-25

### Added
- **Record Entries**: A new entry type keeps the lowest or highest value of a path with the moment it was reached, or the time since the path was last at or above, or at or below, a level. A lowest or highest value starts again every day, week, month or year, whenever the input reaches a level, when another path resets, or only by hand; "the lowest charge since the battery was last full" is a lowest value of the state of charge that starts again at 100 %. A time since is published in whole seconds, grows every second, is 0 while the input is at the level, and is shown on the status page in days and hours. The moment that goes with the record can be published on a second path, **Path for the time**, as an ISO 8601 date and time; while the input stays at the level it is sent at most once a minute. A **Start value** and **Start time** take in a moment the plugin could not see, within the time the record covers. Values are dated by the system clock and not taken in while the clock is recognisably unset; a value from before the time the record covers, such as one the server held from before a boundary at start-up, starts a record that holds nothing yet only as the boundary would have, dated at the start of that time, and a moment dated by a clock that ran ahead is moved back once the clock is right. The record is saved with the totals; a change of its input, what it keeps, its level or when it starts again starts it again, and the editor says so before saving. **Start again** on the status page, or the reset route, starts a lowest or highest value again from the input's latest value; a time since has no reset.
- **Fill In From History**: A counter, integration, cycles entry or record that starts with nothing saved, as a new entry does or one whose total a change discarded, reads the history another plugin keeps, through the History API of Signal K server 2.33 and later, and fills in the time before it started. A counter or integration adds what its input did from the start of the current period, or from the last fall of the path it follows, a cycles entry finds the stretches of its window, and a record finds the lowest or highest value since it last started again, or the last moment the input was at the level. Each entry's own rules are applied to the history, read in buckets of at least one second and at most 40,000 buckets a read, up to the moment the entry began counting, so nothing is counted twice. The last fall of a followed path, the last moment at a level and a lowest or highest value are found to the second; where the history holds no fall of a followed path, nothing is filled in, as the start of the total is not known. A restart never reads the history; a restart or an edit before the history has been read carries the reading on, up to the same moment. A read that takes longer than 120 seconds is given up and asks the provider nothing further. Without a provider the entry asks again every 30 seconds for 15 minutes, as providers are plugins that start in no set order. The field **Fill in from history**, on by default, switches it off per entry. The status page says what was filled in, over which stretch, or why nothing was, and the status route reports it as `history`. Checked end to end against Signal K server 2.34.0 with a provider that answers as `signalk-to-influxdb2` 2.3.0 does: a day's counter and integration, a day of compressor cycles, the lowest charge since full and the time since full.
- **Unit of a Record's Input**: The status route reports `inputUnit` for a record, the unit in which its levels are set, so the status page shows a level of 1 on a ratio as 100 %.

### Changed
- **Status Page Details**: Under each entry the state now stands alone, with a message only when there is one, such as why the entry is waiting, and the details follow as a list of labelled facts, one a line: what the entry reads, when it resets or starts again, when it was last reset, the figures of a cycles entry, what was filled in from history. The label sits beside its value on a wide screen and above it on a narrow one. Until now all of it ran on as one paragraph after the state, in which a fact was hard to find. Paths wrap only after a dot, so a segment with a hyphen, such as `port-aft`, no longer breaks at its hyphen, and no name breaks in the middle.
- **Years in Dates**: The status page adds the year to a date more than 300 days away, as a record or the history may hold one.
- **Kelvin on the Status Page**: A record in kelvin is shown in °C, as a formula is: it holds a temperature, not a sum or a difference.
- **Documentation**: The README describes records and filling in from history in the order the editor shows their fields, with a worked example for a battery, and lists their limits. "Averages and Extremes" under Future Enhancements is now "Averages", as a record covers the lowest and highest value over a period. `docs/upgrading.md` describes going back to 0.7.0.

## [0.7.0] - 2026-10-23

### Added
- **ON Time So Far**: A Cycles entry can publish the length of the ON stretch under way: 0 while the device rests, growing by the second while it runs, and counted past the longest stretch. The median of finished stretches leaves out a stretch longer than the longest stretch, so a compressor that never stops did not show in any figure; an alert on the ON time so far catches it as it happens. It needs no cycles in the window, so **Window** and **Cycles needed** are not shown for it, and a value there that cannot be used is no fault. For this figure a wave input that goes flat while ON stays ON, since a compressor that does not stop leaves the humidity or temperature at its lowest; every other figure still leaves such a wave out after the longest stretch. The status route reports it as `cycles.onSoFar`.
- **Closing Total of a Period**: At each period boundary a counter or integration publishes the total the period closed at, stamped one millisecond before the boundary, and then 0. A database that stores the output thus holds each day's final figure at the end of that day, where it showed only the last figure sent before midnight. The closing total is recorded in the reset record as `lastReset.total`, saved with the state, and shown on the status page ("the day closed at 2.4 kWh"). A change of time zone that begins a new date closes the total the same way, dated just before the change. A clock that ran ahead and was set back by less than five minutes passes a boundary twice; the second closing total is then the whole period, with the same time stamp. A boundary that passed while the plugin was stopped is recorded but not published, and nothing is published for an entry that is not publishing at the boundary. Entries that read the total are not handed the closing total. Checked against Signal K server 2.34.0, which stores and forwards the time stamp; a server started with `--override-timestamps`, as Signal K's plugin CI does, replaces it with the time of arrival.
- **Unit Warning**: The editor points out a unit that Signal K does not define, such as `kWh`, under the **Unit** field. The list is the units of the Signal K specification. Such a unit can still be saved and is published as given.
- **Status Page Without a Connection**: When the server cannot be reached or answers with an error, the status page keeps the readings it last received, dimmed, and says at the top since when they have not been updated. Until now the readings stayed as they were, marked only by a line at the foot of the page, and an error answer cleared them. A refusal of access and a plugin that is not running still clear the readings and say why; a 503 from something other than the plugin, such as a proxy in front of a server that is restarting, keeps them.
- **Everyday Units**: The status page shows pascals as hPa, radians as degrees, radians per second as degrees per second and coulombs as Ah, with the published value beneath as for other units.

### Changed
- **Counter Glitches**: A period counter that counts increases or decreases with "Carry on counting from the new value" now holds back a value that moves the other way until the next one. If the next value is back at the earlier level, within the smallest change to count, or beyond, the held value was a glitch, such as a single 0 from a device that is starting, and nothing is added; until now the whole climb back from it was counted. If not, the source has restarted, and counting carries on from the new level as before. The held value is saved with the state. "Wait until the previous level is passed again" and "Net change" are unchanged.
- **Integration Across a Boundary**: The stretch between an integration's last value before a boundary and the boundary itself is now added to the period that ends, at the last value, and counted in its closing total. Until now it was left out of both periods, up to one sampling interval per boundary. It is added only where the stretch is not a gap, or is bridged.
- **Clock Set After a Boot**: When a computer starts with its clock unset and the clock is then set to a time after a period boundary, the plugin works out from the monotonic clock when it started. If the start came after the boundary, what was counted since then stays in the new period and the total saved before closes the period that ended; until now everything went to the period that ended, and the new day started from zero although it had been counted. A start before the boundary is handled as before, as the moment of the boundary cannot be told. The status page says which. An edit of the entry in between keeps the moment of the start; a restart of the plugin begins it again.
- **Following Another Path's Resets**: "When another path resets" now clears the total when the followed value falls to below half of the value before, or to zero. Until now any fall, however small, cleared it, so rounding noise on a followed daily yield could reset a total in the middle of the day. A smaller fall moves the level the next fall is measured from, so a total that slips down in small steps and then drops to zero resets once, at the zero. At the first value after a start or an edit any fall still counts, so a device that began its new day while the plugin was stopped is followed as before.
- **Turning Points on a Plateau**: Among equal step means the latest is now taken, so a wave that holds at its top or bottom, such as humidity at 100 %, turns where it moves away from the plateau rather than where it reached it. The stretches either side of such a plateau were up to its length too long or too short. Readings that vary a little across a plateau are not affected.
- **Order of a Counter's Fields**: In the editor a period counter's **Count**, **When the input moves the other way** and **Smallest change to count** now come straight after **Input path**, before **Output path**, as an integration's **Add up** and **Threshold** do.
- **Release Order**: The publish workflow now publishes to npm before it creates the GitHub Release, so a release is never shown for a version that npm does not have.
- **Documentation**: The README lists the fields of each entry type in the order the editor shows them, with defaults throughout; version notes take one form; history of earlier versions is left to this file and to the pages under `docs/`. Prerequisites and the Quick Start Guide come straight after the features. The upgrade notes for 0.2.x and the worked time zone examples moved to `docs/upgrading.md` and `docs/time-zones.md`.

### Fixed
- **Units and Names Left Behind**: A unit or name taken out of an entry stayed on the server, and so did the unit and name of an output path given up by a rename, a switch-off or a delete. The server cannot delete metadata, so the plugin now overwrites what it announced before with empty values (`units` and `displayName` null, `description` empty). Only what changed is sent after an edit.
- **Output on the Time Zone Path**: An entry whose output was the path the time zone is read from fed its own result back as the zone. It is now a fault on its output path and stops the save.
- **Contrast of Warnings**: The orange used for "(unsaved)" and the editor status in the light theme was below the contrast WCAG asks for normal text. It is now darker.

### Security
- **Reset Requests Must Be JSON**: The reset route now answers 415 unless the request is sent with `Content-Type: application/json`. A plain form on another site can send a cross-site request without that header, and could otherwise have cleared a total in a browser logged in to the server. The status page sends it.
- **Pinned Workflow Actions**: The publish workflow uses each action at a fixed commit rather than a moving tag, gives the workflow no permissions by default and the job only those it needs, installs npm 11 rather than whatever is latest, and does not keep the checkout's credentials. The CI workflow reads the repository only.

## [0.6.1] - 2026-10-23

### Fixed
- **Entries That Read Another Entry Went Stale**: An entry whose input is another entry's result judged that input by the age of its last value. An entry sends its result when it changes, so a result that held, such as a running-time total while the switch it sums is off, aged past the reader's stale timeout, and the reader stopped and sent null although nothing was wrong. Such an input now counts as fresh for as long as the entry that produces it is publishing and not stale. An integration over such a result goes on adding it at the value it holds.
- **Plugin Switched Off Could Run Again**: After a start with an `entries.json` that could not be used, switching the plugin off left the editor's save route able to start the calculations again, which then published while the server listed the plugin as off. The routes that read or change the entries, the reset route and the preview now answer 503 while the plugin is not running.
- **State File Overwritten After a Read Error**: A `state.json` that could not be read at all, for example after a disk error, was replaced by the next save, losing every total in it. The plugin now leaves such a file alone, saves nothing until a restart reads it, and says so in the plugin status. A file that was read but is damaged is moved aside as before. Each save also flushes the folder after replacing the file, so that a power cut just after a save is less likely to bring the old file back.
- **Lost Value When Sending Failed**: A value that could not be handed to the server was recorded as sent, so with the repeat interval at 0 it went out only when it next changed. It now goes out again at the next pass.
- **Settings That Were Not Numbers Read as 0**: A numeric setting saved as text that is not a number, such as `1.234,5` for a threshold, was read as 0 or as the default. It is now a fault on that field and stops the save. A number with a decimal comma, such as `1,5`, is read as 1.5, also where an earlier version saved it as text and read it as 0 or as the default; a comma followed by exactly three digits, such as `1,500`, could separate thousands and is refused with that reason. After the update, an entry saved by an earlier version with such a setting either shows the fault and stops until the setting is corrected, or, where the comma is now read, runs on the value written; a counter, integration or cycles entry whose threshold, smallest change or stale timeout now reads differently starts its total or its cycles again, as after any change of that setting. Blank text means the default, also for a stale timeout, which read it as 0.
- **Formula Names**: A function name that every JavaScript object carries, such as `isPrototypeOf(a)`, passed the formula check and gave 0. A formula may now name only its inputs, the documented functions and the constants `E`, `PI`, `true` and `false`. The message for a refused short name states the rule as it is applied.
- **Time Zone Spellings**: A followed zone name in another letter case, such as `europe/athens`, counted as a different zone, which was recorded as a change of zone that was none and kept a formatter for every spelling. Letter case is now taken as the server's runtime writes the name. A different name for the same zone, such as `US/Pacific` for `America/Los_Angeles`, is still a different name, and is shown as given.
- **Cycles Kept Old Stretches After a Clock Correction**: A wall clock that ran ahead, even briefly, stopped finished stretches from leaving the window until real time caught up, so the figures included stretches older than the window. The window is now applied at both ends.
- **Cycles Cut a Stretch Just Under the Longest Stretch**: A wave that had not turned for the longest stretch was measured from its last turning point, which is found minutes after it happens, so a stretch a few minutes shorter than the longest stretch was left out. It is now measured from the moment the turn was found.
- **A Total Too Large to Hold**: A total that would no longer be a finite number was set to 0 without a reset record. It now keeps its value and the addition is left out, as the status message says.
- **Editor Showed an Outdated Set**: The editor kept the set it read first, so after a save from another browser the next save here was refused. With nothing unsaved, it now loads a newer set when it is shown and on its 10-second refresh; with unsaved changes, it says at once that the set was changed elsewhere.
- **Formula Preview Showed an Older Result**: An answer to an earlier preview request could arrive last and replace the result of the expression shown, and a result stayed shown while the server could not be reached. Older answers are now ignored, and a failed request says that the formula was not checked.
- **Import**: A file with an entry type such as `__proto__` failed without a word. Every import now ends with a notice; files over 1 MB are refused; and entry and group ids that the server would refuse are replaced.
- **Keyboard Focus**: After a refused save, a conflict, a failed save while offline, and a reset on the status page, the keyboard focus was lost. It now moves to the notice that explains what happened, or stays on the button.
- **Status Page on Slow Connections**: The page asked for the status every 2 seconds whether or not the last answer had come, so requests piled up on a slow link and an older answer could be drawn last. It now waits for each answer.
- **Decimal Comma**: A number typed with a decimal comma, as a phone set to a comma region offers, was saved as text, and then refused or read as 0 depending on the field. The editor and the server now read the comma as the decimal point, as described under the settings above.
- **Older Safari**: The status page did not work in Safari before 16.4, including iPads that cannot update beyond iPadOS 15, because of a regular expression feature those versions lack. The page now uses only what Safari 15 offers.
- **Screen Readers**: The notices of the status page were announced again at every refresh, and the outcome of a reset was not announced. Notices now change only when their text does, and the outcome is announced once.
- **Editing Bar on Small Screens**: The editing bar that stays at the top of the editor could cover the field that had the keyboard focus. The page now scrolls a focused field clear of it.
- **Text Dragged Into a Field**: Text dragged into a field of an entry was taken for an entry being moved. Only entries are handled as entries now.
- **Documentation**: The README, the field help and the OpenAPI description were corrected where they no longer matched the plugin, including that a save must name the revision it is based on, which routes answer 503, when the state is saved, the rules for short names, the limits on a set of entries, and the units the status page shows. Sections on updating and uninstalling were added, and CONTRIBUTING describes the current layout.

### Security
- **Formula Preview Limits**: The preview route accepted an expression of any length, and one very long expression could hold the server busy for seconds. It now refuses what a save refuses: an expression or path longer than 500 characters, more than 50 inputs, and short names a save would not accept.
- **Server Errors**: An unexpected error while saving answered with its message, which could name the server's folders. The answer is now a fixed text, and the details go to the server log.

## [0.6.0] - 2026-10-19

### Changed
- **Null When an Entry Stops Publishing**: An entry that stops publishing now sends null once on its output path. Until now it only stopped sending, and the server went on serving its last result, so a reader that takes the latest value of a path without checking its age, such as a forecast that learns from it, kept using a figure that was no longer current. Null means "no reading", as it does on any input. It is sent for every reason an entry stops: a stale input with "Stop publishing"; a formula input with no reading or no number, or a formula with no finite result; a cycles entry whose figure drops out, for example after **Forget cycles**; and an edit that switches an entry off, deletes it or gives it another output path, which sends null on the path it published before. The result is sent again as soon as there is one. "Keep publishing the last result" still holds the last result through a stale input, and only then: a result withdrawn for any other reason sends null with either setting. Nothing is sent for a path the plugin has not published since it started, nor when the plugin stops, since the server removes the plugin's values itself. The status page adds "Null was sent on" and the path to the entry's message once null has gone out, also for an entry switched off. Checked against Signal K server 2.33.0 and 2.34.0: the server stores the null and serves it as `null` through its REST interface and to plugins that read the path with `getSelfPath()`.

### Fixed
- **Totals Lost on a Restart From the Admin UI**: A restart from the admin UI ends the server process without stopping its plugins, so up to 30 seconds of an integration's total could be lost. The plugin now also saves its totals as the process ends. From server 2.34.0 a stop by signal, such as `systemctl restart`, stops the plugins first, which saved already.
- **Help for Value When Stale**: The field's help now says that the value is also used when the input has had no value since the entry was last changed, as the README and the status page do. The editor screenshot in the README shows the field.

## [0.5.0] - 2026-10-19

### Added
- **Value When Stale for Formula Inputs**: Each input of a formula can be given a value that the formula uses while the input is stale, has had no value since the plugin started or the entry was last changed, or holds `null` or a value that is not a number, which is also what another entry it reads sends while that entry is not publishing. An input with such a value never makes the entry wait or go stale, so a device that leaves the bus, such as a shore charger at anchor, can count as `0` and a house load worked out from the sources keeps publishing. The switch happens at the stale timeout, also when no other input changes, and at once for a value the server held at start-up that is already older than that; the input's own value is used again as soon as one arrives. Inputs left empty behave as before. An entry whose inputs all have a value when stale always publishes; leaving one input without a value is how to make it stop when its devices are silent. The value is given in the unit Signal K publishes for the path and saved in the entries file only when set, so entries saved by earlier versions read unchanged.
- **Editor**: Each formula input has a **Value when stale** box with the input's published unit beside it. A value that is not a number is refused on saving, and its box is marked. The live preview uses the values when stale for the inputs that are stale or have no value at the moment, takes the entry's stale timeout into account, and names the inputs it replaced.
- **Status Page**: A formula names each input counted as its value when stale, with the value used and why: no value for longer than the stale timeout, no value since the plugin started or the entry was last changed, or no number at the moment. A result held while another input is stale keeps listing the inputs it was worked out with.
- **HTTP Interface**: The preview route takes `whenStale` per input and the entry's `staleTimeout`, and answers with `substituted`, the inputs it replaced, when there are any. The status route reports `substituted`, `staleTimeout` and `edited` for each formula.

## [0.4.2] - 2026-10-16

### Added
- **Expand All and Collapse All**: The editor has an **Expand all** button in its editing bar for every entry, and one beside each group's name for that group's entries; while there are groups, the block of entries outside any group has one too. The status page has one above its groups when there are two or more. Each button is named after what it will do: it expands everything in its scope while anything there is collapsed, and turns into **Collapse all** once all is expanded. On a phone the editor's button sits under **More**. The status page now keeps collapsed groups for as long as the page is open also in a browser that stores no site data; until now its groups expanded again at the next refresh there.

### Changed
- **Collapse Instead of Fold**: The page and the README say "collapse" and "expand" where they said "fold". What each browser remembers about collapsed status groups carries over.

### Fixed
- **Header and Footer Empty in the Editor**: Opened straight on **Edit entries**, the page left the line under its title (the time zone in use) and the footer (the time of the last update, the time the plugin started and its version) empty, because both were filled only by the status refresh, which runs while the Status tab shows. They are now filled when the page opens on either tab, and kept current every 10 seconds while the editor shows; an editor that could not reach the server at first tries again on the same beat. The fault dates from 0.3.0.

## [0.4.1] - 2026-10-15

### Added
- **Units in the Editor**: The threshold and swing of a cycles input, the threshold of an integration that adds up time and the smallest change of a period counter are shown and entered in the unit the Signal K rules editor uses for the input path: °C for a temperature, % for a ratio such as humidity, hPa for a pressure, any other unit as published. The unit appears beside the field's title. Values are still kept in the unit Signal K publishes, so a humidity swing typed as `1` % is saved as `0.01`, and entries saved by 0.4.0 read unchanged.
- **Current Value in the Shown Unit**: The hint under a path field gives the current value in the same unit, with the value as published beside it, for example "Now 62.5 % (0.625 ratio as published)". Under a formula's inputs the value as published leads, since a formula calculates with it. A number typed before the path's unit is known takes the unit shown once it is: `1` typed before a humidity path is chosen is 1 %.
- **Every Fault at Its Field**: A refused save lists every fault of an entry, not only the first, and marks each field a fault lies in. A fault, and its mark, are dropped as soon as its field is changed. A smoothing too long is a fault only when an input is read as a wave, since the field is hidden otherwise. The save route also returns `entryFaults`, every fault with its field, beside `entryErrors`.
- **Folding on Narrow Screens**: On a phone each field's explanation folds behind a **Help** button beside its title, and **Add group**, **Export** and **Import** fold behind **More**, so the editing bar that stays at the top takes one line instead of two.

### Changed
- **Entries Closed After Saving and Discarding**: A save closes every entry, except one the server reports a fault in and except when entries were changed while the save was on its way, and **Discard changes** closes them all. Open entries stayed open before, which left a long page after each save.
- **Unsaved Changes Compared, Not Counted**: The editor reports unsaved changes only while the set differs from the saved one. An edit undone by hand, such as adding an input and removing it again, no longer leaves "Unsaved changes" behind.
- **Larger Touch Targets**: On touch screens the "Edit plugin configuration" link, the **Switched on** check box and the group headings of the status page are larger.

### Fixed
- **New Group Out of Sight**: **Add group** focused the new group's name, which is added at the end of the page, without bringing it into view. The group is now scrolled to the middle of the screen with its name selected.
- **Focus Lost on Removing an Input**: Removing an input of a formula or a cycles entry left the keyboard focus nowhere. It now moves to the input in its place, or to **Add input**.
- **Escape Ignored in Confirmations**: Escape, pressed while the focus is on a step that asks for confirmation, now cancels it: in the editor **Delete entry**, **Delete group**, **Discard changes** and the question before a save that costs a total, and on the status page **Reset to zero** and **Forget cycles**.

## [0.4.0] - 2026-10-15

### Added
- **Cycles**: A fourth entry type finds the ON and OFF stretches of a device that cycles, such as a fridge or freezer compressor, a pump or a heater, and publishes one figure over a window such as the last 24 hours: the median ON time, the median OFF time, the median cycle, the duty cycle, the last ON time or the number of cycles. Each input is read as on/off against a threshold, which suits a switch or a current, or as a wave that rises and falls with the device, which suits the temperature or humidity inside a fridge. Two or more inputs are combined as the conditions of a rule: ON while all of them are ON, or while any of them is. A brief flicker stays inside the stretch it interrupts, stretches longer than a set limit are left out, an input with nothing to say is left out of the combination, and a figure is published only once the window holds enough cycles. The finished stretches survive a restart. The status page shows every figure and the latest stretch found, and its **Forget cycles** button starts the figures again, for example after a defrost. The README explains how the inputs are read and combined, how combining inputs that respond with a delay changes the lengths read, how to choose the swing of a wave, and how to set an alert limit for a defrost.
- **Status Route Fields for Cycles**: Each cycles entry reports `combine`, `statistic`, `window`, `minCycles`, `cycleInputs` and a `cycles` object with every figure, the latest stretch found and how long ago it began.

### Changed
- **Going Back to 0.3.0**: Version 0.3.0 refuses an `entries.json` that holds a cycles entry, so cycles entries must be deleted before going back. The README describes the steps.
- **Reset Route**: `POST /api/entries/{id}/reset` also makes a cycles entry forget the cycles counted.
- **Save Warning**: The editor's question before a save that costs something now reads "Saving changes what these entries have counted", and names a cycles entry whose stretches would be forgotten.

## [0.3.0] - 2026-10-15

### Added
- **Entry Editor**: Entries are created and changed on the plugin's page under Webapps, in a new **Edit entries** tab, instead of in the plugin settings form. Path fields suggest the paths the server knows and show each path's current value and unit; a formula shows its result with the current values as it is typed; each entry says which entries it reads from and which read from it; fields that apply only to some settings appear only then. The forms are built from the same field definitions the settings form used, so titles and explanations are unchanged. The tab appears for users with read/write or admin access.
- **Groups and Order**: Entries can be sorted into groups named by the user and ordered within them, by dragging with a mouse or with arrow buttons. The status page shows the entries outside any group first, without a heading, then a heading per group in the chosen order; each group can be folded away, and each browser remembers which are. Groups change only what is shown.
- **Saving Without Interruption**: A save restarts only the entries whose calculation changed. Entries left alone, or changed only in name, unit or group, keep running as they were, mid-stretch, so nothing they were adding up is lost. A started entry is handed the latest value of each path it reads at once. A running entry that reads a restarted one adds up the stretch to the save as usual. Before a save that costs a total (an entry deleted, or its output path, input path, direction, integration mode, threshold or reset rule changed, compared by output path) the page lists what is lost and asks first. A set with an entry that is switched on and cannot run is refused whole, with the fault shown at the entry; an entry that is switched off may be saved unfinished. A save must name the version of the entries it was based on, and one based on an older version is refused, so two browsers cannot overwrite each other unawares. Fields of the wrong kind are dropped, ids such as `constructor` are refused, and a set is limited to 1 MB.
- **Import and Export**: The set of entries and groups can be exported as a file and imported again, as a backup or to carry it to another server.
- **Editor Routes**: `GET` and `PUT /api/config` read and save the entries with their revision, `GET /api/paths` lists the vessel's paths with values and units, and `POST /api/preview` works out a formula without saving it. All four need read/write access and are described in the OpenAPI document.
- **Everyday Units for Speed and Distance**: The status page shows `m/s` also in knots, and `m` from one nautical mile up also in nautical miles.

### Changed
- **Entries Kept in Their Own File**: Entries and groups are kept in `entries.json` in the plugin's data directory. The plugin settings keep the time zone, day start, week start and repeat interval. On the first start of this version the entries are moved out of the settings in the order the status page showed them, a copy of the settings as they were is kept as `settings-before-0.3.0.json`, and the lists are removed from the settings; every total carries on. Restoring the copy is the way back to 0.2.1; the README describes it, including which totals 0.2.1 does not keep. An `entries.json` that cannot be read is left untouched and reported, and nothing runs or is saved until a new set is saved, which is written in full before the old file is moved aside.
- **Unused Totals Kept for 30 Days**: A saved total whose output no entry uses when the plugin starts is kept in the state file for 30 days instead of being dropped at the next save, so an entry with that output that comes back continues its total. Up to 0.2.1 such a total was dropped at once. A total of an entry deleted in the editor is dropped at once, after the editor's warning.
- **Link to the Settings**: The link at the top of the plugin's page reads "Edit plugin configuration". "Edit entries" read as if the values on the page could be edited.
- **Paths in Sentences**: Paths named in the sentences of the status page, such as the path the time zone is read from, are set in a code font.
- **Status Route**: Each entry's `key` is now its id in the entries file, and each entry names its `group`; the route also returns the `groups` in order and one-time `notes`, such as the report that entries were moved.

### Fixed
- **Restart Loss Stated Correctly**: The README said totals are saved on a clean stop. Signal K server 2.33 ends its process on a restart without stopping its plugins, so a restart of the server can lose up to 30 seconds of an integration's total, as a power cut can. The README now says so. The behaviour is unchanged.

## [0.2.1] - 2026-10-11

### Added
- **Reset Record**: Each counter and integration records when and why its total was last cleared: a new period, a change of time zone that jumped over a boundary, the followed path falling, or a request. For a followed path the record holds the value it fell from, the value it fell to and the source of the lower value. The status page shows the record under the entry, the status route reports it as `lastReset`, and it is saved with the total. A start time that was replaced without clearing the total, after a clock correction, is recorded the same way as `sinceCorrected`. A total that starts again at an unexpected time now states the reason.
- **Zone Change Record**: The status page states the last change of the followed time zone, or of the path it is read from, with the time and both zones. The status route reports it as `timeZoneSource.lastChange`.
- **Plugin Start Time**: The status page and the status route (`startedAt`) state when the plugin last started.

### Fixed
- **Saved Totals Missing After a Restart**: A counter or integration restored from the state file showed "Waiting" and published nothing until its input sent a value, whatever its stale setting. After a server restart with an engine switched off, a daily engine total therefore disappeared until the engine was next switched on. A restored total is now the entry's value from the start. It is shown with the text "No value on ... since the plugin started": as stale, and published when the entry is set to keep publishing its last result; or, for an entry with a stale timeout of zero, as publishing. It is passed to the entries that read it whenever it is published. It still rolls over at its period boundary while the input stays silent. One pass runs as soon as the plugin starts, so a boundary that passed during downtime is applied before the status is first read.
- **Chained Counter Missing a Boundary After a Restart**: A counter that reads another entry's total now receives a restored total that is being published, and the zero that follows a boundary passed during downtime. Before, it heard nothing until the restored entry's own input had spoken, and then counted the difference to the value from before the stop. Its total after such a restart now matches what a boundary seen live produces.
- **Total Cleared by a Value the Server Still Held**: The server keeps the last value of every source that ever wrote to a path and replays them all, oldest first, when the plugin starts. Where a device had appeared under two source names, a total that resets when a path falls saw the old name's last value followed by the current one and was cleared at every plugin start; a period counter on such a path counted the difference. One held value per path is now used at start-up: the one the server itself reports for the path, or the held value with the newest time stamp. The paths that carry the ship's time zone are treated the same way, so an old source's zone is no longer recorded as a change at every start.
- **Old Values Read as New**: The server can also hand over a held value while the plugin runs. A value from a source other than the one last read is now ignored when it repeats exactly what that source sent before (same time stamp, same value), or, from a source not seen before on that path, when it is older than the value last read. Every value held at start-up counts as seen. A time stamp from the future counts as the moment of arrival. The zone tracker likewise ignores a value from another source that is older than the one it holds for a path. The status page counts the ignored input values and names the last one; the status route reports them as `outdatedValues`. Values from the source last read are never ignored, so a replayed log is still read.
- **List Descriptions Shown Twice ([signalk-server#3143](https://github.com/SignalK/signalk-server/issues/3143))**: The settings form showed the description of the Formulas, Period counters and Integrations lists twice, once above each heading and once below it. The Admin UI of Signal K server 2.33 prints a list's description in both places, so the three lists no longer carry one; the plugin's description at the top of the form says what each list holds.

## [0.2.0] - 2026-10-10

### Added
- **Ship's Time Zone**: Day, week, month and year boundaries can follow the time zone the vessel keeps, read from Signal K. The standard paths `environment.time.timezoneRegion` (a zone name) and `environment.time.timezoneOffset` (hours and minutes as one number) are read by default, so a plugin such as Ship's Time is followed without any setup. A name is preferred to an offset; an offset published later than the name, and disagreeing with it, takes over. This is the default for new and existing installations; with nothing published on those paths the behaviour is as before. An installation where Ship's Time is still at its default of manual mode and offset zero will follow UTC until that plugin is configured.
- **Configurable Paths for the Zone**: The two paths can be changed, for installations where custom code or another plugin publishes the zone elsewhere. Either path accepts a zone name, a fixed offset written as text, or the specification's number form.
- **Zone Changes Follow the Calendar**: A total belongs to a calendar date and is cleared when a later date begins, never twice for the same date. A change of zone therefore behaves like a daylight saving change: going east over a boundary starts the new period at once, and going west back over a boundary carries the period on until the next one begins. The status page explains either case on the entry concerned.
- **Remembered Zone**: The last zone followed is saved with the totals and used after a restart until the source publishes again, so a restart cannot move a day boundary.
- **Time Zone List**: The time zone setting is now a list holding the server's own zone, UTC, the fixed offsets from UTC-12:00 to UTC+14:00 including the part-hour ones, and the zone names the runtime knows. Fixed offsets are new; they do not follow daylight saving, and the list says so. A zone saved earlier that the list does not hold is added to it, so opening and saving the form never replaces it.
- **Zone in the Status**: The status page states the zone in use and where it comes from, the status route reports the same as `timeZoneLabel` and `timeZoneSource`, and the plugin's status line names a followed zone. A value on a followed path that is not a zone is reported on the status page.
- **Full Changelog Link in Releases**: Each GitHub Release now ends with a link to the comparison with the previous version.

### Changed
- **Time Zone Setting**: The setting is renamed "Time zone when none is published" and is the fallback when the ship's time is followed. A zone name saved by version 0.1.0 keeps working, and an empty value still means the server's own zone. To keep a fixed zone regardless of what is published, "Time zone for day boundaries" is set to "Always use the time zone chosen below".
- **State File**: Each period total now records the calendar date of its period and the zone that date was read in, next to the start instant, and the file holds the last zone followed. State written by version 0.1.0 is taken over with its totals, and the file remains readable by 0.1.0.
- **Release Workflow**: The release action moved to `softprops/action-gh-release@v3`, which runs on Node 24.

## [0.1.0] - 2026-10-10

### Added
- **Formulas**: An entry type that publishes the result of an expression over any number of live paths and constants. Each input path is given a short name, because paths contain dots and dashes that an expression would read as operators. Expressions are parsed by `expr-eval-fork` with assignment, function definitions, arrays, string concatenation and property access switched off, and are never passed to JavaScript's `eval`.
- **Period Counters**: An entry type that publishes how much a running total has changed since the start of the day, week, month or year, or since a manual reset. It can count increases only, decreases only (a falling tank level becomes consumption) or the net change, with a smallest-change setting that keeps sensor ripple out of the total.
- **Integrations**: An entry type that adds up an input over time. One mode multiplies the value by the elapsed time (power into energy, flow into volume); the other adds up the time the input spends above a threshold (engine running time, time a switch is on). A regularly sampled input is joined by straight lines between values, and an input with a stale timeout of `0` is held at its last value and extended every second.
- **Selectable Resets**: Period boundaries are computed in a configurable IANA time zone with a configurable start of day and first day of the week, including on the 23-hour and 25-hour days of a daylight saving change. As an alternative, a total can reset whenever another path's value falls, so that a calculated daily total keeps step with a device that resets its own daily figure at its own time.
- **Chaining**: An entry can use another entry's output as an input. Entries are calculated in dependency order, each once per incoming update, so values that arrive together are applied together. A reset, a period rollover, a missing result and a stale input all reach the entries downstream. Entries that feed each other in a loop are refused with a message while the remaining entries run.
- **Stale Input Handling**: A per-entry stale timeout, with a per-entry choice between stopping publication and continuing to publish the last result. A formula is not recalculated while one of its inputs is stale. For integrations, a gap longer than the timeout is left out of the total by default and can optionally be bridged with the last value.
- **State Persistence**: Totals, baselines and period starts are saved to `state.json` in the plugin's data directory every 30 seconds when changed, on stop and at every reset. The file is written to a temporary file, flushed to disk and renamed over the previous one, so an interrupted save leaves the old file or the new one, and it is rewritten in place, so it does not grow.
- **Clock Safety**: Elapsed time is measured on a monotonic clock, and period resets pause while the system clock reads earlier than 2024 or earlier than the last saved state. A computer without a clock battery that boots at 1970 therefore neither resets its totals nor counts the correction as elapsed time. A clock that is wrong but plausible cannot be detected.
- **Unit Metadata**: Each output path is announced with its unit, display name and description, so the Data Browser and instrument displays can label it.
- **Status Page**: A page under Webapps lists every entry with its current value, state, explanatory message and the time counting began, and offers a reset button with a confirmation step for counters and integrations. Values are shown in an everyday unit with the published SI value beneath.
- **HTTP Interface**: `GET /plugins/signalk-calc-paths/api/entries` returns every entry's status, and `POST /plugins/signalk-calc-paths/api/entries/{output path}/reset` clears one total. Reading is open to any logged-in user and resetting to read/write and admin users through the server's per-route access levels; on servers without that feature both routes stay admin-only. An OpenAPI description is registered with the server.
- **Automated Tests**: A test suite covering period boundaries across time zones and daylight saving changes, formula parsing and its restrictions, every counter and integration mode, chained entries, restarts, clock faults, configuration checking, state storage and the plugin's interaction with the server API, plus an end-to-end check that runs against a live Signal K server in CI.
